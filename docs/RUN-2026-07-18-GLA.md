# GLA Hybrid: First Measurements (2026-07-18)

Machine: local 16-core CPU (multicore backend). Model: the GLA 3:1 hybrid
(docs/ATTENTION-SEMANTICS.md), commit series on branch `attention-semantics`.

## Training-step cost: `bench_grad` ladder (multicore, batch=1)

Same dataset shapes as the recorded softmax ladders (HANDOFF 2026-07-16),
now denoting hybrid models — points with fewer than four layers are pure
GLA; the six-layer points carry one softmax layer. Hybrid shapes also carry
more parameters (one d×d gate projection per GLA layer).

| shape (v/d/f/h/L/n) | softmax post-fix | hybrid |
|---|---:|---:|
| tiny 258/16/48/2/1/16 | 0.85 ms | 1.08 ms |
| small 258/64/192/4/2/64 | 16.9 ms | 22.1 ms |
| vocab 8192/64/192/4/2/64 | — (59.0 pre-fix) | 55.6 ms |
| context 258/64/192/4/2/256 | — (184 pre-fix) | 119.7 ms |
| dim 258/320/192/5/2/64 | — (211 pre-fix) | 151.5 ms |
| ff 258/64/864/4/2/64 | — (38.2 pre-fix) | 37.3 ms |
| layers 258/64/192/4/6/64 | — (69.3 pre-fix) | 60.0 ms |
| bpe10m-shape 8192/320/864/5/6/256 | 2.52 s | 3.09 s |

Honest reading: within a training window the GLA parallel closed form is
the same O(n²·d) complexity class as masked softmax, with extra work (the
gate projection, log-gates, prefix sums, per-element exp in the decay
scores), so per-step training cost at these shapes is near parity, not a
win (~1.2–1.3× at equal shape with more parameters). The measured wins of
the semantics are elsewhere:

1. **Decode time** — the fixed-state decoder (below) replaces
   O(window·model) per token with O(model).
2. **The chunkwise form** — `chunk-closed` is GEMM-shaped; a tensor-core
   backend for training is the licensed follow-up, not micro-optimizing
   the current FP32 map/reduce schedule.

## Quality: gla-small on wiki-sample vs the bigram gate

Setup: `train data/wiki-sample.corpus run/gla-small.checkpoint 5000
gla-small`, TRAIN_BATCH=4, MICRO_BATCH=4, VALIDATE_EVERY=250,
VALIDATION_WINDOWS=64, multicore backend. gla-small = Config 258 64 64 192
4 4 (three GLA layers + one softmax, 242,368 parameters).

Bigram gate on this corpus/split: **sample 2.4922 / full 2.5742 nats**.

Recorded softmax baselines for context (2-layer, 123,328-parameter `small`
— half the parameters and half the depth, so directional only): best
validation 1.9468 nats after a 5000-step run; 1.1868 nats after a full
epoch (52,852 steps).

Results:

- **Validation 2.0532 nats (2.9622 bits/byte) at step 5000, still
  improving** (2.0740 at 4000, 2.0537 at 4750). **Beats the bigram gate
  from step 1250 onward**; every validation line from there is
  `beats-gate`, four `behind-gate` lines before it.
- Speed: the full 5000-step run took ~13 minutes on the 16-core multicore
  backend (~6.4 updates/s at TRAIN_BATCH=4, ~1,600 target tokens/s),
  validation and checkpoints included.
- Sampled text (temperature 0.8, top-k 40) is early-training
  byte-English of the same character as the softmax small model at
  comparable depth into training: wiki-register fragments, no factual
  content, no degenerate repetition loop.

Directional comparison: the 2-layer softmax `small` reached 1.9468 at
5000 steps and 1.1868 after a 52,852-step epoch, under an earlier
sampler/window regime and with half the parameters — so the numbers are
not aligned enough to rank architectures; the load-bearing result is that
the hybrid trains stably, clears the non-neural gate quickly, and tracks
the same quality class at matched step count. The epoch-scale and
bpe-scale comparisons are the next measurements.

## The controlled A/B: softmax vs hybrid (2026-07-19)

The missing comparison, run locally after the rented server was retired.
Softmax arm: master's architecture with the new depth-matched `small4`
preset (Config 258 64 64 192 4 4, 230,080 params, RoPE — it IS the old
architecture). Hybrid arm: this branch's `gla-small` (242,368 params, +5%
from the gate projections). Identical regime both arms: wiki-sample,
TRAIN_BATCH=4, MICRO_BATCH=4, 5000 steps, VALIDATE_EVERY=250,
VALIDATION_WINDOWS=64, multicore backend, identical bigram gate
(2.4922 sample / 2.5742 full — same split by construction).

| arm | params | best val @5000 | bits/byte | gate crossed | wall |
|---|---:|---:|---:|---:|---:|
| softmax `small4` (master) | 230,080 | **2.0510** | 2.9590 | step 1000 | ~11 min |
| GLA 3:1 hybrid `gla-small` | 242,368 | **2.0532** | 2.9622 | step 1250 | ~13 min |

**Verdict: quality parity.** The 0.0022-nat (~0.1%) difference is noise;
the softmax arm is marginally ahead and ~15–20% faster per step at this
scale. At a 64-token window and 2 MB of bytes, softmax's quadratic cost is
trivial and its exact retrieval is free — exactly the regime where the
Kimi Linear paper also finds linear attention pays nothing yet. The
hybrid's measured wins are decode-time cost and the proof-carrying
semantics; its projected wins (long context, the chunkwise GEMM form on
tensor cores) need scale this machine cannot reach.

Like-for-like generation (same prompt/seed/budget, 128 tokens, best of 3,
each arm generating from its own 5000-step checkpoint):

| arm | wall for 128-token budget |
|---|---:|
| softmax, full-window recompute per token | 0.48 s |
| hybrid, fixed-state decode per token | **0.23 s** |

2× end-to-end at the scale where recompute is cheapest (n=64, 230k
params, startup included); the recompute path grows with window and model
size (measured 321 ms per full forward at the bpe-scale shape ≈ per-token
cost) while the decode path stays O(model) per token.

## Chunkwise GLA (Stage A, 2026-07-19)

The training forward now runs the GEMM-shaped chunkwise form
(`gla_attention_chunked`), licensed by `chunk-closed`. Operator equality vs
the retained quadratic form is exact up to f32 reassociation: conformance
`chunked vs quadratic GLA logits` ~7e-9, `tests.fut` equivalence at chunk
1/2/3/6, gradient gates run at chunk 2.

Quality regression, gla-small 5000 steps at GEMM_CHUNK=16 (four chunks of 16
over the 64-token window, so the cross-chunk state carry is exercised):

| run | best val (nats) | bpb | gate crossed | wall |
|---|---:|---:|---:|---:|
| quadratic GLA (2026-07-18) | 2.0532 | 2.9622 | step 1250 | ~13 min |
| chunkwise GLA (GEMM_CHUNK=16) | 2.0671 | 2.9824 | step 1000 | ~12 min |

The 0.0139-nat difference is f32 trajectory divergence (the two executions
are equal per-forward only up to ~7e-9 reassociation, which compounds over
5000 optimization steps), not an operator difference — within the ±0.02
gate. Multicore bench: the context-axis gradient point (n=256) fell 119.7 →
68.7 ms; the bpe-scale point ~8% (attention's FLOP share there). The
chunkwise form's decisive win is GEMM shape for a tensor-core backend and
n/C scaling at long context, not raw multicore FLOPs.

## Decoder throughput

The incremental decoder (decode_step; conformance-verified against the
batch forward at max_abs≈6e-9) replaces one full-window forward per token
with one O(model) step per token:

- Measured end-to-end: **~128 generated tokens in 0.24 s wall** (0.22 s
  for a 16-token budget — the process is startup-dominated), i.e. >500
  tokens/s at gla-small scale on the multicore backend, checkpoint load
  and prompt priming included.
- Arithmetic accounting: the old path cost one window forward per token
  (2.0 ms at the 2-layer small shape, 321 ms at the bpe-scale shape,
  measured by `bench_forward`); the decode step costs roughly forward/n —
  a factor that reaches the window length (64 here, 256 at bpe scale)
  once the window is full. The previously recorded sequential-host figure
  at bpe10m scale was ~1.7 s/token; the decoder's per-token arithmetic at
  that shape is ~1.3 ms plus host overhead.
- Beyond the window, per-token cost stays flat: the GLA state is never
  rebuilt (the StateAlgebra run) and the NoPE ring buffer replaces
  sliding-window recomputation.
