# First Training Run: 2026-07-10

## Corpus

The first run uses a bounded sample from
`~/datasets/wikipedia-en/titled-200mb.txt`:

```text
documents: 32
ordinary byte tokens: 262,144
tokenizer: lossless-byte-v1:bos=0:eos=1:bytes=2..257
dataset fingerprint: fnv1a64-noncryptographic:18e9b7a1cfc27813
```

The source prefix was divided into 32 fixed 8 KiB documents before creation of
`CorpusArtifact`. The trainer then performed its deterministic document-level
training/validation split before constructing windows.

The generated data and run artifacts are intentionally ignored by Git:

```text
data/wiki-sample.corpus
data/wiki-sample-docs/

```

## Model And Optimizer

```text
preset: small
vocabulary: 258
context: 64 bytes
model dimension: 64
feed-forward dimension: 192
layers: 2
heads: 4
parameters: 123,328
batch: 1 sequence
target: 1,000 completed steps
checkpoint interval: 10 steps
```

The optimizer is AdamW with a `3e-4` base learning rate, 100-step warmup,
cosine decay, and layout-directed weight decay.

## OpenCL Attempt

The initial two-step OpenCL smoke run did not complete. The client reported:

```text
amdgpu: The CS has cancelled because the context is lost. This context is innocent.
```

The previous boot's kernel journal records a compute-ring timeout and successful
GPU reset at `16:45:31`. It identifies Brave's GPU process as the timed-out
context. Because X and Rusticl share the same Polaris RX 580, the reset caused
the graphical session to disappear. The compute load may have exposed the
driver instability even though the kernel did not blame the trainer's context.

After this event, the host was changed to:

- default to `TRAIN_BATCH=1`;
- set the OpenCL group-size default to 64;
- line-buffer progress logs;
- write atomic checkpoints every `CHECKPOINT_EVERY` steps;
- provide a sequential-C application generated from the same Futhark source.

No second OpenCL run was attempted on the display-attached device.

## Sequential-C Run

The safe smoke run completed first:

```text
step 1 train_loss=5.7812843
step 2 train_loss=5.653548 validation_loss=5.5110717
```

The subsequent 1,000-step run completed successfully. Selected validation
cross-entropies:

| Step | Validation loss |
|---:|---:|
| 10 | 5.5123463 |
| 100 | 4.2443547 |
| 200 | 3.2138054 |
| 500 | 3.0197546 |
| 700 | 2.9424255 |
| 900 | 2.9110710 |
| 1,000 | 2.9122264 |

The rapid early decrease confirms that tokenization, windowing, VJP, AdamW,
state persistence, and validation are connected correctly. The flattening near
`2.91` indicates the limit of this small byte model and tiny corpus, not a useful
general language model.

## Generation Probe

Greedy sequential generation from the prompt `Category theory is` produced:

```text
Category theory is te te te te te te te te te te te te te te te te te te ...
```

This is expected mode collapse for a 123K-parameter byte model trained on only
256 KiB. The probe validates checkpoint loading and autoregressive execution; it
does not demonstrate language quality.

## Reproduction

```bash
TRAIN_BATCH=1 CHECKPOINT_EVERY=10 \
nix run .#formal-transformer-sequential -- \
  train data/wiki-sample.corpus run/wiki-small-1000.checkpoint 1000 small
```

Generation:

```bash
nix run .#formal-transformer-sequential -- \
  generate run/wiki-small-1000.checkpoint "Category theory is" 80
```

The resulting checkpoint has the same model and layout identity as the OpenCL
application and can be loaded there once that backend is made safe on isolated
hardware or a non-display device.
