## Term                                     -- ana writes from here

quicksort [] = []
quicksort (x:xs) =
  let smallerSorted = quicksort [a | a <- xs, a <= x]
      biggerSorted = quicksort [a | a <- xs, a > x]
  in smallerSorted ++ [x] ++ biggerSorted

GHC accepting it only says it type-checks, so I tested it: on 2,000 random lists with duplicates it agrees with Data.List.sort on every one.

Honest note: this is the textbook quicksort, word for word the one in Learn You a Haskell, so ana has most likely seen it. Other checkpoints sometimes write a version that drops duplicates. It's a demonstration of what a 115M model trained this way already does, not of reasoning.

The few things that aren't Bend are the ones that can't be: the Agda exporter is an Agda backend (Haskell), the Lean checker's driver is Lean, and two tiny C files (a clock and a cuBLAS call).

The meaning first

ana is short for anamorphism, an unfold. A fold consumes a structure down to a value; an unfold grows one from a seed for as long as you keep asking. That is autoregressive generation: from a state, emit a token and a next state. bend/Spec/Autoregressive.bend states the model as that coalgebra, and sampling is its unfold into the trie of continuations (bend/Spec/Trie.bend).

The design follows Conal Elliott's denotational design: say what the model means, prove the laws on the meaning, and make the fast code a refinement of it. The spec covers the semiring algebra, weighted languages, the trie, decoding and speculative decoding, the residual stream, linear attention, the tied head, attention sinks, reverse mode, and Tai-Danae Bradley's enriched-category reading of language. It was first written in Agda and is now Bend:

A hybrid stack: three gated linear-attention layers for every softmax layer, with RG-LRU gates, qk-norm, attention sinks and a tied head. The tokenizer, code32k, is a byte-level BPE trained for code.

The trainer

The dense trainer is Bend compiled to CUDA. Before it was trusted, it had to agree with the slow tree trainer: its gradients match the CPU's to within 4.5e-7 relative, on an RTX 3090 and on an RTX 5090. When the project moved from its earlier Haskell trainer to Bend, the Bend run continued the Haskell one step for step (loss within ~5e-6), and greedy decoding was byte-identical.

The GPUs are rented by the hour on vast.ai, from about $0.50/h, and the Bend tools in bend/Box/ stage the data, run the chain of stages, pull and verify checkpoints, and destroy the box when it ends.

The data: ana acts, the compiler answers

ana is trained as a coding agent for functional languages. Its episodes are transcripts: a task, ana's ## Term, then the real tool's answer (ghc, agda, lean, bend, nix) and ana again, up to four turns. Every compiler message it reads was produced by the compiler. It never writes a tool's answer itself: the tool's turns are context, not training targets.

  • Raw code in its five languages: 232,923 Haskell, 23,608 Nix, 16,007 Lean, 8,112 Agda and 1,667 Bend files.
  • Transcripts built from that code by the real checkers: direct tasks (write it) and repairs (fix a wrong attempt).
  • On-policy rounds: ana's own episodes, run on the box against the real compilers, become new training data: its successes, and its rejected terms followed by the known fix.

Results, honestly

99 held-out tasks across the five languages. E1: ana's first answer is accepted by the real checker. E5: accepted within four calls, reading the checker's answers in between.

checkpointE1E5
run 3, s2-step56725 (the one that wrote the quicksort)32/9937/99
run 2, v2-step5388019/9925/99

Run 3 against run 2: p = 0.00 on E1 and 0.01 on E5 (paired, exact McNemar). E1 by language at run 3's end: Haskell 15/31, Bend 4/6, Agda 3/7, Lean 9/46, Nix 1/9.

What these numbers don't say: "accepted" means it type-checks, not that it's right. When a call fails, ana still resubmits nearly the same term most of the time, so it has barely learnt to read errors yet. Run 4, a first real on-policy round, didn't move the agent measures. There is no instruction tuning. This is a small model, early, and every number here can be reproduced from the repo.

Earlier versions were trained on English: v1 (10.6M parameters) reached 1.21 bits per byte on held-out Wikipedia; the 115M v2 reached 1.37 bpb on enwik8.

What's open

  • Source: all of it, MIT. The spec, the model, the trainer, the decoder, the evals, the corpus tools and the run tools.
  • Proofs: bend bend/Everything.bend checks them on your machine.
  • Data: the tools and recipes that build every corpus, and the two tokenizers in weights/.
  • Weights: the 115M checkpoints go on Hugging Face (link here when they're up). The 10.6M v1 checkpoint is in git at the tag haskell-final.
  • Records: HANDOFF.md and docs/ log every run, decision, failure and eval.

Try it

git clone https://github.com/hhefesto/ana && cd ana
nix run .#bend -- bend/Everything.bend    # check the spec: ALL PROOFS CHECK
nix flake check                           # spec, unit tests, trainer and dense-trainer checks
nix develop                               # bend, ghc, agda, lean
nix run .#ana -- --checkpoint PATH "quicksort"   # generate from a checkpoint

TEMPERATURE, TOP_K, TOP_P and SAMPLE_SEED control sampling.
