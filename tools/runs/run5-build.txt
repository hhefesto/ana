# 5. Bend's filler: every stream's files, each id once, none holding a held-out unit, in keyed order, so that each
#    shard's slice has every size.  A window needs a filler file of its own in its shard, and sessions fill about two
#    a window, so plan-windows reads them K times (FILLER_COPIES, step 7; 11-03: filler-union's copies=K wrote 14 GB
#    first, about 3 hours on one core for what one pass does).

CV keyed-order nul "run 5 filler" ALL.nul run/v6/R5src/bend/files-hi.nul
